# 0060. Security pass: library holes, a stricter CSP

Date: 2026-11-16. Status: accepted.

## Context

The development overlay said Next.js 16.4.3 had a known hole, and the owner
asked for it to be fixed and for the site's defences to be checked.
`npm audit` and `pip-audit` found:

- **maplibre-gl ≤ 6.4.0, critical** (GHSA-jrc7-96c5-q579): its cleaning of a
  map's credit line could be slipped past, running script from a credit.
  FishEye builds the credit from the style and its TileJSON, which come from
  the map provider, and Leaflet writes it into the page without cleaning it.
- **next 16.3.0–16.4.4, moderate** (GHSA-mfr8-8qww-v76h): `use cache` with
  `unstable_cache`, which FishEye doesn't use.
- **starlette 0.38.6** (under FastAPI 0.115): form parsing with no bound on
  field size or count, a blocking roll-over of large uploads, and request
  URLs rebuilt from the Host header and an unchecked path. Photo uploads go
  through this parser.
- Lint and test tools only: typescript-eslint, minimatch, pytest.
- `onnx` 1.18 in `requirements-semantic.txt`: used only to build models on
  a developer's machine, never loaded by the server. Left for now.

What was already in place, checked and left as it is: scrypt password
hashes compared in constant time; session tokens stored as hashes in an
httpOnly, SameSite=Lax cookie, Secure over HTTPS; CORS limited to the site;
a same-origin check on admin and write routes; per-visitor and login rate
limits; body size caps; uploads re-encoded with their EXIF (and GPS)
dropped; admin endpoints closed when no token is set; no public API docs;
HTTPS with HSTS; the site never framed.

## Decision

- **Upgrade.** Next.js 16.4.6, maplibre-gl 6.18.0, FastAPI 0.163.1 with
  Starlette 1.10.0, pytest 9.0.3; `npm audit fix` for the lint tools.
  `npm audit` now finds nothing; `pip-audit` finds only onnx.
- **MapLibre 6 needs its worker served by us.** It is ESM only and looks for
  its worker beside its own file, which bundling moves, so the map failed
  with "Worker failed to load". `scripts/copy-maplibre-worker.mjs` copies
  it to `public/maplibre/` before `next dev` and `next build`, and
  `BaseMap.tsx` points MapLibre at it. MapLibre 6 also needs WebGL2;
  without it the raster tiles are drawn.
- **The credit line is cleaned by FishEye** (`safeCredit` in
  `lib/map/basemapStyle.ts`): text and `https` links only, whatever the
  libraries do.
- **A stricter CSP on production pages** (`next.config.ts`): scripts only
  from the site, connections only to the site and the map hosts named in
  the build's settings, images from any https host (photos, raster tiles),
  no frames, no plugins, forms only to the site. Inline scripts stay
  allowed because Next.js writes page data inline; a nonce would make
  every page render per request. `next dev` keeps the short policy, since
  its live reload needs eval and a websocket.
- **The API's answers carry `default-src 'none'`**, and uvicorn no longer
  names itself in a `Server` header.

## Consequences

- A new map provider, or any new script, font or fetch from another host,
  is blocked until its host is added. It shows up as a CSP error in the
  browser console.
- The production build was checked page by page in headless Chrome
  (home, map, a lake, fish, gear, handbook, Ask, questions, rules, sources,
  start, community, login, identify, privacy). There were no CSP blocks
  and no errors, and a script or fetch aimed at another host was refused.
  The satellite style (MapTiler, billed per request) was not loaded. Its
  host is allowed by the same setting that names it.

## Not done

- Nonce-based CSP (drops `'unsafe-inline'` for scripts): every page would
  become dynamic and uncached.
- `includeSubDomains` and preload for HSTS: a commitment for every
  subdomain, for little gain while the site has one.
- Server-level checks (firewall, SSH, OS updates): outside this repository.
