# **1 产品结论**

这个产品具备明确的实际价值，也适合使用 LLM 和其他 AI 能力，但不应把 LLM
当作事实数据库。最稳妥的产品结构是：地图负责位置与交互，政府和专业数据源负责湖泊、鱼种、法规与天气，规则或评分模型负责生成候选钓点，LLM
负责解释、个性化建议、自然语言问答和多源信息摘要。

第一版不需要覆盖全美国，首发范围只做 Texas，录入 5 至 10
个精选淡水水域，并优先选择用户朋友实际方便到达、能够协助实地测试的 3
个水域。第一版优先完成从选湖到获得一份可执行钓鱼计划的闭环。地图上的系统点位应称为候选钓点或推荐区域，并显示依据、数据时间和置信度；Verified
用户提交的社区地图钉应明确标记为社区信息，不能被包装成官方事实或保证钓获。

# **2 产品定位**

FishPilot AI
是一款面向淡水钓鱼新手的地图型决策助手。用户不需要先了解鱼种习性、天气、水域结构、装备参数和当地信息，只需选择一个州、湖泊或目标鱼，系统就将可靠数据整理为易懂且可执行的出钓方案。

  ----------------------------------------------------------------------------------------------------------------
  **项目**                            **定义**
  ----------------------------------- ----------------------------------------------------------------------------
  目标用户                            刚开始钓鱼、搬到新城市、不熟悉当地湖泊，或希望快速规划一次出钓的人

  核心问题                            用户知道想钓鱼，但不知道去哪、钓什么、什么时候去、站在哪里、用什么装备

  核心价值                            把分散在地图、州政府网站、天气服务和钓鱼资料中的信息整合为一条简单决策路径

  首发范围                            Texas 淡水岸钓场景；首批 5 至 10 个精选水域，其中 3 个用于朋友实地测试

  差异化                              可解释的地图建议、新手行动清单，以及经过身份验证用户贡献的社区点位信息
  ----------------------------------------------------------------------------------------------------------------

# **3 用户使用流程**

1\. 用户打开地图，允许定位或进入 Texas
水域列表；系统优先显示已收录且便于实地测试的水域。

2\. 系统显示已收录湖泊，并按距离、目标鱼、岸钓友好程度和当前条件筛选。

3\.
用户点开一个湖泊，查看湖泊简介、公共入口、常见鱼种、近期天气、法规链接和数据更新时间。

4\. 用户点选目标鱼，例如 largemouth bass、walleye 或 catfish。

5\.
系统结合鱼种习性、季节、时间、气温、风、降水和可获得的水域结构数据生成候选钓点。

6\. 系统给出推荐钓竿、线组、鱼钩、拟饵或活饵、操作方法以及新手注意事项。

7\.
用户查看地图上的社区钓鱼信息；完成真人身份验证的用户可添加地图钉，分享鱼种观察和具体岸边、堤坝、桥区或公园钓位经验。

8\. 系统显示附近鱼饵店或户外用品店，并允许跳转到 Google Maps
查看路线和距离。

9\. 用户继续向 AI 助手提问，例如 我只有一根 6 英尺 6
英寸纺车竿应该怎么配。

# **4 核心功能需求**

## **4.1 地图与湖泊发现**

-   显示州边界、湖泊标记、用户当前位置和地图筛选器。

-   支持按州、城市、湖名、距离和目标鱼搜索。

-   湖泊详情至少包含名称、坐标、公共入口、允许的钓鱼方式、常见鱼种、官方来源和数据更新时间。

-   Google Maps JavaScript API 可用于交互地图、自定义标记和数据图层；MVP
    可以先使用二维地图和卫星图切换。

## **4.2 鱼种信息**

-   每个湖泊展示已确认或高可信度出现的鱼种，不直接把全州鱼种列表等同于该湖鱼种。

-   鱼种卡片包括常见名称、英文名、偏好水温、季节、活跃时段、栖息结构、常见深度、天气偏好和新手难度。

-   每条关键事实保留来源、适用地区和更新时间，方便纠错和后续更新。

## **4.3 天气与出钓建议**

-   获取当前天气、未来小时预报、降水、风速、风向、温度和恶劣天气预警。

-   根据目标鱼和天气生成适合时段、岸边方向、饵色和操作速度建议。

-   天气建议需要解释原因，例如
    风把饵鱼推向迎风岸，因此可优先检查迎风岸的公共入口。

-   若出现雷暴、强风、洪水或极端高温预警，安全信息必须优先于钓鱼推荐。

## **4.4 候选钓点推荐**

Google Maps
本身不会可靠地告诉系统哪里一定有水草、倒木、落差或鱼群。因此，推荐点应由多种证据组合产生，而不是让
LLM 直接看地图后随意给坐标。

  ---------------------------------------------------------------------------------------------------------------
  **信号**                **用途**                                           **MVP 可行性**
  ----------------------- -------------------------------------------------- ------------------------------------
  公共入口和岸钓区        先排除无法合法进入或不适合岸钓的区域               高，可由官方页面和人工录入

  岸线形状                识别岬角、湾口、桥区、入水口等结构                 中，可由地理数据加规则计算

  水深和等深线            判断落差、浅滩与深水邻接关系                       取决于湖泊是否有公开测深数据

  天气和风向              根据当天条件调整优先岸线和作钓时段                 高，可接入天气 API

  卫星影像特征            未来识别可见水草、浅水颜色或倒木线索               后续功能，需确认影像授权与准确性

  Verified 社区地图钉     补充鱼种观察、岸钓位置和现场经验，不替代官方数据   MVP
                                                                             可做，需验证、审核、举报和时效控制
  ---------------------------------------------------------------------------------------------------------------

每个候选点显示 0 到 100
的匹配分、推荐原因、适用鱼种、适合时间、步行或停车提示、数据来源和置信度。系统不得把私人岸线、封闭区域或未经确认的地块标记为可进入。

## **4.5 装备与鱼饵推荐**

-   输入目标鱼、钓法、预算、已有装备和经验等级。

-   输出钓竿长度与调性、轮型、主线、前导线、鱼钩或拟饵规格、推荐颜色、结法和操作步骤。

-   同时提供低预算方案、通用方案和升级方案，但 MVP
    可以先只显示通用新手方案。

-   推荐必须区分通用知识与当天条件产生的调整，不应伪装成实时库存或保证效果。

## **4.6 周边鱼饵店与路线**

-   以湖泊或候选钓点为中心，通过 Places Nearby Search 查询 bait
    shop、fishing store、sporting goods store 等相关地点。

-   显示店名、地址、营业状态、评分和距离，仅请求界面需要的字段以控制费用。

-   点击后打开 Google Maps 路线；MVP 不必在应用内实现完整导航。

## **4.7 法规与安全**

-   显示州级钓鱼执照入口、目标鱼尺寸和数量限制的官方链接，以及湖泊特殊规则。

-   法规属于高风险动态信息。应用只做摘要，必须展示官方来源、更新时间和以官方页面为准的提示。

-   加入天气预警、洪水、结冰、船坡关闭、入侵物种和私人土地提醒。

## **4.8 Verified 用户社区地图钉**

社区地图钉是官方数据与系统推荐之外的补充信息源。所有用户都可以查看；只有已通过真人身份验证、状态正常且非机器人账户的用户可以创建地图钉。Verified
只表示账号完成身份核验，不代表其每条内容必然正确。

  --------------------------------------------------------------------------------------------------------------------------
  **能力**                            **MVP 规则**
  ----------------------------------- --------------------------------------------------------------------------------------
  地图钉类型                          钓获报告、鱼种观察、岸边或桥区建议、堤坝或入水口经验、通行与停车提示、风险或封闭提醒

  必要字段                            坐标、水域、类型、说明、观察时间；鱼种、钓法、饵和照片为可选项

  社区互动                            查看评论、回复、有帮助投票和举报；创建者可编辑或删除自己的地图钉

  可信度标签                          显示 Verified 作者徽章、社区报告标签、发布时间、最近确认时间和审核状态

  内容治理                            支持自动规则、用户举报和管理员审核；过期地图钉应降权、要求重新确认或自动隐藏
  --------------------------------------------------------------------------------------------------------------------------

-   身份服务仅向产品返回 verification_status 和外部 provider
    reference；前端、地图钉和评论中不得展示真实姓名、证件号码或证件照片。

-   地图钉不得鼓励翻越围栏、进入私人土地、在禁止区域钓鱼或停留在危险桥面和泄洪设施；涉及封闭、危险或违法内容时应隐藏并进入审核。

-   对生态敏感鱼种、脆弱产卵区或容易被过度捕捞的位置，应模糊精确坐标、限制传播或移除。

-   社区内容不能覆盖官方通行状态、法规或天气警告；当信息冲突时，优先展示官方来源并提示用户举报或核实。

# **5 AI 与 LLM 设计**

  --------------------------------------------------------------------------------------------------------
  **任务**                **是否适合 LLM**        **推荐实现**
  ----------------------- ----------------------- --------------------------------------------------------
  解释鱼种习性            适合                    从已审核知识库检索事实后，让 LLM 用新手语言解释

  根据用户装备给建议      适合                    将结构化装备规则和用户条件一并传入模型

  总结多个来源            适合                    使用 RAG，保留来源与更新时间

  总结社区地图钉          有限适合                只使用近期且审核通过的内容，明确区分官方事实与社区观察

  自然语言问答            适合                    限制在当前湖泊、鱼种和可用数据范围内回答

  判断湖里有没有某种鱼    不应单独决定            使用 DNR、调查、放流或已审核湖泊数据

  直接生成精确钓点坐标    不应单独决定            先由地理规则和公开入口生成候选点，LLM 只解释原因

  判断法规是否仍有效      不应单独决定            显示官方来源，按更新时间和规则版本控制
  --------------------------------------------------------------------------------------------------------

## **5.1 推荐的 RAG 流程**

1\. 后端接收 lake_id、species_id、时间、用户位置、经验和装备条件。

2\.
从数据库读取湖泊鱼种、公共入口、鱼种知识、法规来源、当天天气，以及近期且审核通过的社区地图钉。

3\. 评分服务生成候选钓点和结构化推荐理由。

4\. 将结构化事实交给 LLM，要求仅基于提供内容生成自然语言说明。

5\. 输出
JSON，包括摘要、推荐时段、装备、饵、操作步骤、风险、来源和置信度。

6\. 服务端校验 JSON
与必填字段，不合格时回退到固定模板，不把模型原始文本直接显示给用户。

## **5.2 候选钓点评分模型**

MVP 先使用可解释的加权规则，不需要训练机器学习模型。一个示例公式如下：

**Spot Score = Access 40% + Weather 25% + Species Match 20% + Freshness
15%**

（原始示例公式为 Access 30% + Habitat 25% + Weather 20% + Species Match
15% + Freshness 10%。2026-09-24
起去掉了 Habitat 这一项：项目没有测深/水草数据源的接入计划，保留一个永远返回"缺失"的维度只会让每次打分白白扣 25%
置信度。它的权重按比例分摊给了其余四项，见
`docs/adr/0013-drop-habitat-and-water-temperature.md`。同一次改动也去掉了
Weather 内部的水温子信号，理由相同——NWS 只提供气温，项目没有真实水温数据源。若未来接入测深/水草或水温数据，应重新把它们加回各自的权重结构，而不是让"缺失"成为永久状态。）

若缺少某项信号，不要把缺失项当作零分，而应降低置信度并重新归一化已有信号。近期、多人确认且审核通过的社区地图钉可以作为单独的
Community Evidence
调整项，但不能覆盖公共通行状态、法规或天气预警。后续积累足够反馈后，再用学习排序模型调整权重。

# **12 验收标准**

-   用户在 60 秒内能从选择湖泊完成一份出钓建议。

-   每个湖泊鱼种和法规摘要都能追溯到官方来源。

-   地图不会把未经确认的私人区域标为公共入口。

-   没有水深或栖息地数据时，系统明确显示低置信度，不伪造细节。

-   恶劣天气预警覆盖并优先于普通推荐。

-   LLM 返回结构化 JSON，服务端验证失败时显示固定模板建议。

-   Google、天气和 LLM API 密钥不进入前端仓库或 Git 提交。

-   移动端地图、详情抽屉和推荐结果无明显遮挡或无法点击问题。

-   未通过真人验证的账户不能创建地图钉；验证状态由服务端检查，不能只依赖前端按钮隐藏。

-   地图钉显示社区报告标签、作者 Verified
    徽章、观察时间与审核状态，不暗示内容已被官方确认。

-   证件图片、证件号码和真实姓名不出现在地图钉、公开资料、日志或客户端
    API 响应中。

-   用户能够举报危险、违法、虚假、骚扰或暴露隐私的地图钉；管理员能够隐藏、恢复和记录处置原因。

## **12.1 Texas 朋友实地测试计划**

首轮测试由用户邀请的 Texas 本地朋友完成。先选择他们实际方便到达的 3
个公共水域，使用固定任务验证产品是否真的能帮助新手完成出钓准备，而不只是在演示环境中看起来可用。

-   测试任务：选择水域和目标鱼，查看天气与法规，获得候选钓点和装备建议，查找附近鱼饵店，并尝试提交一条社区地图钉。

-   记录指标：任务完成率、完成时间、卡住的步骤、错误信息、推荐可信度评分和愿不愿意再次使用。

-   现场核对：公共入口是否真实可达，路线是否正确，推荐岸线是否安全，鱼种与法规来源是否匹配当前水域。

-   反馈方式：提供简短问卷和问题截图；测试者可以选择分享实际钓况，但不要求公开精确敏感钓点。

-   迭代标准：先修复阻断核心流程的问题，再处理推荐解释、界面易用性和非关键功能；每次修复后复测同一任务。

-   作品集证据：在获得测试者同意并去除个人信息后，将测试任务、发现的问题、修复前后结果和关键指标写入
    evaluation report。
